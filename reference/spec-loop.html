Reference · Workflow

The spec loop

One small feature, specced, built in watched steps, reviewed, and run.

The loop

  1. Predict. Before writing anything, sketch the nodes and files you expect the feature to need.
  2. Spec. Write specs/NNNN-name.md, about 10 lines at most. If it won't fit, it's more than one feature.
  3. Build in steps. Ask the agent to implement the spec one step at a time, stopping after each one with a short explanation.
  4. Review each step. Check it against the list below before saying "next".
  5. Run it. Play the scene and check every "done when" line by hand.
  6. Compare. Open the result in the editor and compare it with your prediction. The differences are where the learning is.
  7. Commit. One spec, one commit.

Spec template

# NNNN · Feature name

Goal: one sentence, from the player's point of view.

Behaviour:
- ...
- ...

Done when:
- an observable check you can do by playing
- ...

Not in this spec:
- the tempting next thing, written down so it stays out

The "Not in this spec" list matters more than it looks. It's how you stop the agent, and yourself, from adding "while we're here" changes.

Step review checklist

CheckWhy
Only does what this step saidChanges outside the step aren't reviewed.
Right node type for the jobSee the glossary, especially the four body types.
Static types (var speed: float, -> void)Catches errors at parse time and makes reviews easier.
Input via actions, never raw keycodesGamepad and Steam Deck support depend on it.
No delta before move_and_slide()The engine already applies it.
Follows the style guidesnake_case functions and variables, PascalCase classes, tabs.
I can explain every lineIf you can't, ask before moving on.

What to say to the agent

Implement specs/0001-paddle.md one step at a time.
After each step, stop, show me what changed, and explain why.
Don't start the next step until I say "next".

Commands the agent uses

CommandDoes
godot --versionConfirms the installed engine version.
godot --path . --importOpens the project headless, imports resources, quits. Catches broken scenes.
godot --path . --headless --quit-after 60Runs the main scene for 60 frames without a window. Use it as a smoke test.
godot --path . -eOpens the editor on this project.

Source: Command line tutorial. Godot silently ignores unknown flags, so a typo won't produce an error.
