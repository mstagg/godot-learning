Glossary

The words every lesson uses, with the same meaning each time.

Terms are added as lessons introduce them. If a lesson uses a word differently from this page, the page wins, so tell your teacher.

Engine structure

Node
The basic building block. Each node type does one job (draw a sprite, detect collisions, play a sound). Nodes have a name, properties, and per-frame callbacks, and any node can have children. Docs
Scene
A tree of nodes saved to a .tscn file, with exactly one root node. Once saved, a scene acts like a new node type: you can drop it inside another scene as a single node. Docs
Root node
The top node of a scene. Its type usually defines what the scene is, e.g. a paddle scene's root is a CharacterBody2D.
Scene tree
The live tree of all nodes while the game runs. A game is a tree of scenes, and each scene is a tree of nodes.
Instance
One copy of a scene placed inside another. Ten bricks are ten instances of one Brick scene. Docs
Main scene
The scene Godot loads first when the game runs. Set in Project Settings.

Input

Input action
A named input, like move_left, that any number of keys, buttons or sticks can trigger. Game code checks actions, not raw keys, so remapping and gamepad support come for free. Name actions in snake_case. Docs
Input Map
The Project Settings tab where actions are defined and bound to events. Stored in project.godot.
Input.get_axis(neg, pos)
Returns a float from −1 to 1: the strength of pos minus the strength of neg. One call gives left/right direction. Docs
Polling vs events
Polling checks input state every frame (Input.is_action_pressed), for held actions like movement. Events arrive in _input(event) once per press, for one-off actions like jump.

Physics & movement

CharacterBody2D
A body that detects collisions but has no built-in physics. Your code moves it. Use it for players, enemies, and paddles. Docs
StaticBody2D
A body that collides but never moves in response. Use it for walls and floors.
RigidBody2D
A body the physics engine simulates. You apply forces instead of setting its position.
Area2D
Detects overlaps and emits signals when bodies enter or exit. Doesn't block movement.
CollisionShape2D
The child node that gives a body or area its shape. A body with no shape collides with nothing.
velocity
A CharacterBody2D property: the speed and direction in pixels per second. You set it, then call move_and_slide().
move_and_slide()
Moves the body by velocity, slides along whatever it hits, and applies the physics delta itself. Don't multiply velocity by delta before calling it. Docs
motion_mode
Grounded for side-view games with floors and ceilings. Floating when there's no floor (top-down games, a Breakout paddle).

The frame loop

_physics_process(delta)
Runs at a fixed rate (60/s by default) before each physics step. Movement and anything touching bodies goes here.
_process(delta)
Runs once per rendered frame, which varies. Use it for visuals that don't touch physics.
delta
Seconds since the last call. Multiply per-second rates by it, unless the engine already does (see move_and_slide).
