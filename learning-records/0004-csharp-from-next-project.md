# C# trial on the next project

On 2026-11-05 the learner chose C# for the next game project (the clone after Breakout, Galaga on the draft roadmap). Breakout stays in GDScript and finishes on the standard Godot build. The next project needs the Godot .NET build (`brew install --cask godot-mono`) and the .NET SDK, neither of which was installed on 2026-11-05. Install both at that project's setup step. Its CLAUDE.md needs C# conventions instead of the GDScript section (typed by default, `[Export]`, `partial` classes, signals as `[Signal]` delegates, rebuild before running) and a `dotnet build` step in Verify. Lessons should show C# first and point out where the docs' GDScript examples translate. Unit tests (xUnit or gdUnit4) become practical, which suits Tetris. Why: the learner finds GDScript's syntax foreign and unpleasant. They have used C# before, prefer its OOP structure, and their native language is TypeScript, which C# is closer to. It's a trial: they want exposure to the C# bindings and will decide after that project whether to keep C# for later ones. Ask at the end of that project rather than assuming. When explaining C#, TypeScript comparisons will land better than GDScript ones.
