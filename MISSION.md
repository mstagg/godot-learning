# Mission: Godot Game Development (agentic-first)

## Why
Build a solid Godot foundation, so that a later, separate project (an Ogre Battle 64–style tactics game for Steam on desktop and Steam Deck) isn't slowed down by gaps in my engine knowledge. Practise small-increment, spec-driven agentic development habits that legacy work projects don't allow.

## Success looks like
- Build a series of small clones of existing games, starting with NES-era 2D and moving up in complexity through later eras into 3D. Together they touch most of the engine: 2D, 3D, UI, physics, animation, audio, save/load, input, shaders, export.
- Write and run specs for each project (spec-driven dev) and direct an agent to implement them, with tests where Godot allows.
- Explain, in my own words, how scenes, nodes, signals, resources and autoloads fit together, and review all agent-written code critically.
- Export a project to Linux/desktop and run it on a Steam Deck.
- Make simple pixel-art sprites, tilesets and animations by hand, and find and correctly license free assets for anything I don't make.
- Start the tactics game knowing which engine features, patterns and workflows to reach for.

## Constraints
- Professional developer, 10 years experience, manages 10 engineers; learns during the working day, so lessons stay short.
- Target the latest stable Godot (4.7.2 as of 2026-10-20).
- Agentic-first: the agent writes code; the learner writes specs, reviews, and steers. Art assets are the exception: made by hand or sourced from free libraries, never agent-generated.
- Has done some game-dev tutorials and books before, never formally built a game.
- Paints miniatures (traditional colour and value skills), but has no digital art experience.
- Priority order: learning Godot first, agentic practice second.
- Specs are small and very iterative: one feature or request at a time, with the code written in view so no large change slips past review. Never spec a whole game and let the agent run for an hour.
- No communities (forums, Discord, etc.) at this time.

## Out of scope
- Writing all code by hand.
- Other engines (Unity, Unreal).
- Custom engine modules / C++ (for now).
- Generating art assets with agents.
- Multiplayer/networking (for now).
- Building the tactics game itself; that is a separate project.
