Lesson 1 · Breakout clone · about 30 minutes

A paddle that moves

Nodes, scenes and input actions, built from your first five-line spec.

Your win

A Godot 4.7 window where a paddle slides left and right with the arrow keys and stops at the screen edges. You spec it, the agent builds it in steps you watch, and you can explain every node in it.

Breakout is a good first clone because it has very few moving parts: a paddle, a ball, walls and bricks. Each one introduces a single engine idea, and today's is the paddle. What carries forward to your tactics game is the input setup: anything driven by input actions, such as a map cursor or a menu, works on keyboard, gamepad and Steam Deck without extra code.

Three ideas, in five minutes

1. Everything is a node, and nodes make scenes

Nodes are Godot's building blocks. Each node type does one job, and any node can have children.Docs: Nodes and scenes. "Nodes are the fundamental building blocks of your game." A tree of nodes saved to a file is a scene. A scene always has one root node, and once saved it behaves like a new node type you can drop into other scenes.

In software terms, a scene is a component. The paddle will be its own scene, and the game scene will contain one instance of it.

2. Pick the body by who moves it

Godot has four 2D collision types. The question that picks one is who controls the movement?Docs: Physics introduction. A CharacterBody2D's movement "must be controlled by the user via code."

NodeMoved byBreakout use
CharacterBody2DYour codePaddle (today)
StaticBody2DNothingWalls
RigidBody2DPhysics engineUsually not the ball, as we'll see
Area2DDoesn't blockThe "ball fell off" zone

A body needs a CollisionShape2D child, or it collides with nothing. It needs something visible too: for now, a plain coloured rectangle.

3. Read actions, not keys, every physics tick

Define named input actions (move_left, move_right) in the Input Map, and bind keys or gamepad buttons to them.Docs: Input examples. Polling suits held actions like movement, and _input() events suit one-off actions. Movement is a held action, so you poll it in _physics_process, which runs at a fixed 60 times per second.

func _physics_process(_delta: float) -> void:
	var direction := Input.get_axis("move_left", "move_right")  # −1 … 1
	velocity.x = direction * speed
	move_and_slide()

move_and_slide() applies the physics delta for you, so the code doesn't multiply by delta. Multiplying again is the most common bug in agent-written movement code, so look for it.CharacterBody2D reference. move_and_slide uses velocity and the physics step automatically. Input.get_axis returns positive strength minus negative strength.

Do it

  1. Install Godot 4.7.2. 
    brew install --cask godot
godot --version   # expect 4.7.2.stable…
  2. Create the project in the Project Manager. Run open -a Godot, choose Create, name it breakout, and set the folder to ~/learning/godot/projects/breakout. Keep the default renderer for now. Renderers come up again in the Steam Deck lesson. Turn on Git version control if it's offered. Then close Godot.
  3. Ask the agent to set up the agent rules. Say: "Project created. Set up CLAUDE.md, specs/ and git." Read the CLAUDE.md it writes. It's your standing contract with the agent, so change anything you disagree with.
  4. Predict the node tree. On paper or in a comment, write down the paddle scene's nodes: the root type and its children. Don't look anything up. You'll check it in step 7.
  5. Write the spec. Create specs/0001-paddle.md from the template, at most 10 lines. Include the speed, the keys, and what happens at the screen edges. Then compare it with the model below.
    Model spec (open after writing yours) 
    # 0001 · Paddle moves

Goal: the player slides a paddle along the bottom of the screen.

Behaviour:
- Paddle is a wide flat rectangle near the bottom, centred at start.
- Left/right arrows (and A/D) move it at 600 px/s; release stops it instantly.
- It cannot leave the screen.

Done when:
- Running the project shows the paddle; holding each key moves it; it stops at both edges.

Not in this spec:
- Ball, walls, bricks, score, gamepad tuning, art.

    Notice the "Not in this spec" line. Without it, "it cannot leave the screen" might get solved with wall bodies, which belong to a later spec.

  6. Build it in watched steps. Tell the agent: "Implement specs/0001-paddle.md one step at a time. Stop after each step." At each stop, use the review checklist. Expect roughly four steps: input actions, paddle scene, paddle script, main scene. If a step does more than it said, say so.
  7. Run it and compare. Open the editor (godot --path ~/learning/godot/projects/breakout -e) and press Run Project (▶, top right). Check each "Done when" line. Then open paddle.tscn and compare its Scene dock with your prediction from step 4.
  8. Take the quiz below, from memory.

Check yourself

Answer without scrolling up. Effortful recall is what makes it stick, and a wrong answer now is useful.
