Lesson 6 · Fixed shooter, part 1 · about 60 minutes, or two sittings (setup, then specs)

A ship that shoots, in C#

A new project in C#, a pixel-art base resolution from the first minute, and bullets spawned at runtime: scripts in C#, integer scaling, instancing from code, and Timers.

Your win

A new game is running: a crisp pixel-art ship at the bottom of a 320×200 world, scaled ×4 to fill the Steam Deck's 1280×800, sliding left and right and firing a stream of bullets that fly straight however the ship moves. You can read and review Godot C#, say why Position.X = 10 won't compile, and explain where a spawned bullet belongs in the tree.

From last time

CanvasLayer: it draws by its layer number (default 1, above the normal canvas at 0), not by its place in the tree. Tree order only decides draw order within one layer, where later siblings draw on top.

Frames: a frame is never drawn in the middle of a function. _on_ball_lost set GAME_OVER and back to PLAYING in one call, so no frame ever showed GAME_OVER. A state has to persist until a later event changes it.

Input bleed: one Space press fired both confirm and launch. The Game heard it as an event, the paddle by polling is_action_just_pressed, and pausing doesn't swallow a press. You fixed the root cause: one owner reads the key, and the state decides what it means.

Inspector values: a value set in the Inspector is saved in the .tscn and replaces the script's default before _ready runs. That's where levels and starting_level live.

Breakout is done. This project is a fixed shooter in the Galaga and Space Invaders mould: your ship along the bottom, waves of enemies above. Make it your own: your name, your ship, your enemies. It's chosen for what it forces you to learn: scenes spawned at runtime, timers, groups, sprite animation, sound and game states at a bigger scale. It's also your C# trial. You'll decide at the end of the project whether to keep C#.

Part A: set up (about 20 minutes)

  1. Install the .NET SDK. In a terminal: winget install Microsoft.DotNet.SDK.8, or the newer SDK that the Godot download page names. Check with dotnet --version in a new terminal.
  2. Download Godot 4.7.2 .NET. From godotengine.org, take the .NET build for Windows, not the standard one you used for Breakout. Unzip it next to the other one. The two can live side by side, and Breakout keeps using the standard build.
  3. Create the project. Pick your game's name. Create it in projects/<name>/, with the Forward+ renderer. Create one throwaway C# script in the editor (any node, Attach Script, language C#). That makes Godot generate the .csproj and .sln. Delete the script afterwards.
  4. Point Godot at VS Code. Install the C# Dev Kit extension in VS Code. In Godot, go to Editor Settings → Dotnet → Editor → External Editor and choose Visual Studio Code. Double-clicking a script now opens it with IntelliSense.
  5. Set the base resolution (idea 2). In Project Settings, turn on Advanced Settings, then:
    • Display → Window → Size: Viewport Width 320, Viewport Height 200, Window Width Override 1280, Window Height Override 800.
    • Display → Window → Stretch: Mode viewport, Aspect keep, Scale Mode integer.
    • Rendering → Textures → Canvas Textures: Default Texture Filter Nearest.
  6. Tell the agent "project created". It writes the project's CLAUDE.md with C# conventions (idea 1), a dotnet build step in Verify, and a specs/ folder with the same template as Breakout's. Spec numbers start again at 0001.

Four ideas, in fifteen minutes

1. Godot in C#: the same engine, different spelling

Every node, signal and property you know is still there. Only the binding changes. Coming from TypeScript, most of it reads naturally:Docs: C# basics, and C# API differences to GDScript, the page to keep open.

using Godot;

public partial class Ship : CharacterBody2D
{
	[Export] public float Speed { get; set; } = 120f;

	public override void _PhysicsProcess(double delta)
	{
		float direction = Input.GetAxis("move_left", "move_right");
		Velocity = new Vector2(direction * Speed, 0f);
		MoveAndSlide();
	}
}
GDScriptC#Note
extends CharacterBody2Dpublic partial class Ship : CharacterBody2DThe class name must match the file name, Ship.cs. partial is required, because Godot generates the other half.
@export var speed := 120.0[Export] public float Speed { get; set; } = 120f;An attribute, like a TypeScript decorator.
func _ready()public override void _Ready()Engine callbacks keep their underscore; everything else is PascalCase: MoveAndSlide(), QueueFree().
delta: floatdouble deltaDelta is a double, and positions are floats, so you'll write (float)delta.
$CooldownGetNode<Timer>("Cooldown")Typed by a generic, like querySelector<T>.
signal shoot(at)[Signal] public delegate void ShootEventHandler(Vector2 at);Emit with EmitSignal(SignalName.Shoot, pos), connect with ship.Shoot += OnShoot;. The name must end in EventHandler.

One trap catches everyone: Position.X = 10; doesn't compile (error CS1612). Vector2 is a struct, a value type, and Position is a property, so Position hands you a copy. Setting .X on the copy would be silently lost, so C# refuses. Assign a whole vector: Position = new Vector2(10, Position.Y); or Position = Position with { X = 10 };.

C# is compiled. Godot builds the project when you press Play, and errors appear in the editor's MSBuild panel, not the Output panel. After the agent edits a script, the editor needs a rebuild (the hammer icon, or just Play) before the Inspector shows new exports. The self. rule from Breakout becomes this. only if you want it: decide when the agent writes CLAUDE.md.

2. A base resolution, scaled by whole numbers

In Breakout the world was 1280×800, and every sprite needed scaling by 2 (ART_SCALE, nine-patch maths). This time the whole game lives in a 320×200 world, and Godot scales the finished picture up. Viewport stretch mode renders the game at 320×200 and then enlarges the image, so a pixel can never be half a pixel. Integer scale mode only ever enlarges by whole numbers. 320×200 is exactly ¼ of the Steam Deck's 1280×800, so there it's ×4 with no borders. A 1920×1080 monitor gets ×5 (1600×1000) with thin black bars, which is exactly what you want for crisp pixels.Docs: Multiple resolutions. Read the "Stretch mode" and "Stretch scale mode" sections.

What this means for you: draw art at 1:1. A 16×16 ship in Aseprite is a 16×16 ship in the game, positions are in world pixels (the ship sits around y 184), and there's no scale factor anywhere in code.

3. Spawning scenes from code, and where they live

Breakout already instanced bricks from code. Bullets add one decision: which parent. A child inherits its parent's transform, so a bullet added as a child of the ship slides sideways whenever the ship does. Spawned things belong under a node that doesn't move, a Bullets Node2D in the main scene.

That raises the old question: the ship shouldn't reach up the tree to find Bullets. Signals up, calls down. The ship emits Shoot(at) with its nose position, and the main scene, which owns Bullets, instances the bullet:

private void OnShipShoot(Vector2 at)
{
	var bullet = BulletScene.Instantiate<Bullet>();
	bullet.Position = at;
	_bullets.AddChild(bullet);
}

Bullets that leave the screen must free themselves, or they fly up forever and pile up. A VisibleOnScreenNotifier2D child emits ScreenExited when the bullet's rectangle leaves the view; connect it to QueueFree().

4. Timers: "not again until…"

A fire rate is a cooldown, and a Timer node is a cooldown you don't have to count. Set Wait Time to 0.25 and One Shot on, then: if fire is held and _cooldown.IsStopped(), shoot and call _cooldown.Start(). That's at most four shots a second, however fast you press. A Timer counts in the background and emits Timeout when it's done. Here you only ask whether it's still running.Docs: Timer.

Holding fire is polled (Input.IsActionPressed) on purpose. Unlike Breakout's launch, a held button should keep firing. Polling suits "while held", events suit "once per press".

Do it

Use /feature-spec for each spec, and write your own before opening each model. The agent builds a whole spec at once; review it as one diff. The specs are in C# now: review it the way you'd review TypeScript, and ask about any line you can't read.

  1. Optional: draw your ship. A 16×16 sprite in Aseprite, at 1:1, saved to art/ and exported to assets/ as in Breakout. A plain rectangle is fine for now; sprite animation frames get their own lesson.
  2. Spec 0001: the ship moves. Decide: the node type and why, where the ship sits in the 320×200 world, its speed in world pixels per second, the input actions and their bindings, and how it stays on screen.
    Model spec (open after writing yours) 
    # 0001 · Ship moves
Goal: My ship sits at the bottom of the screen and slides left and right, stopping at the edges.
Behaviour:
- Main scene main.tscn (Node2D) with a Ship (CharacterBody2D, scripts/Ship.cs) at (160, 184).
- 16×16 Sprite2D (my ship, or a placeholder) and a matching RectangleShape2D.
- Input actions move_left / move_right: arrow keys, A/D, gamepad d-pad.
- [Export] Speed = 120 world px/s; MoveAndSlide(); X clamped so the whole ship stays on screen.
Done when:
- The window opens at 1280×800, and the ship's pixels are crisp 4×4 blocks.
- Arrows, A/D and the d-pad move it at a steady speed, and it stops flush with both edges.
Not in this spec:
- Shooting
- Enemies
- Ship animation
- A HUD

    Review questions. Does the clamp assign a whole Position (idea 1's trap)? Is delta unused, as it should be with MoveAndSlide()? Are the bindings in the Input Map, not raw keys? And is there any scale factor in the code? There shouldn't be.

  3. Spec 0002: shooting. Decide: the bullet's node type, speed and size, the fire button, the rate, who instances the bullet and where it's added, and how bullets are freed.
    Model spec (open after writing yours) 
    # 0002 · Shooting
Goal: Holding fire shoots a stream of bullets up from the ship's nose, at most four a second.
Behaviour:
- New scene bullet.tscn: Area2D (scripts/Bullet.cs), 2×6 placeholder, moves up at [Export] Speed = 240 px/s.
- A VisibleOnScreenNotifier2D on the bullet; ScreenExited → QueueFree().
- Input action fire: Space, gamepad A.
- Ship: a Timer "Cooldown" (One Shot, 0.25 s). While fire is held and Cooldown is stopped, emit Shoot(nose position) and start Cooldown.
- Main (scripts/Main.cs): [Export] PackedScene BulletScene; on Shoot, instance a bullet at that position under a Bullets Node2D.
Done when:
- Holding Space fires four bullets a second from the nose.
- Bullets fly straight up while the ship moves; they aren't dragged along.
- In the Remote scene tree, Bullets is empty again a second after I stop firing.
Not in this spec:
- Enemies and hits
- A limit on bullets on screen
- Sound

    Review questions. Does the ship know about Bullets or Main? It shouldn't. Is the bullet's movement multiplied by (float)delta, given it isn't using MoveAndSlide()? Is BulletScene set in main.tscn's Inspector, so it isn't null at runtime? And is the signal declared with the EventHandler suffix?

  4. Break it on purpose. Change one line so bullets are added as children of the ship. Fire and move. Describe what you see and why, using idea 3. Then undo it with git checkout.
  5. Spec 0003: two bullets at a time, with no model. Classic fixed shooters allow only a couple of your bullets on screen at once, so aiming matters. Write it alone. Decide how you count bullets on screen, and remember Breakout's last-brick lesson: a QueueFree()d node is still a child until the frame ends. Decide whether the cooldown still applies, and what holding fire does when the limit is reached.
  6. Run it and check. Check every "Done when" line. Resize the window: the picture should jump between whole scales and never blur.
  7. Take the quiz below, from memory.

Push it further

Open-ended, with no model specs. Walk your own path, each with /feature-spec.

  • A starfield. A scrolling background of 1-pixel stars at two speeds for depth. Decide whether stars are nodes, or one node that draws them all in _Draw(). That choice is your first performance trade-off.
  • Ship feel. Acceleration and friction instead of instant speed, so the ship eases in and out. Is it still a CharacterBody2D job?
  • A muzzle flash. One frame of a bright sprite at the nose when firing, hidden by its own short Timer. It's a small preview of the animation lesson.
